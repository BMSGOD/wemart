## What this is

Mobile-first **Nigerian** campus marketplace (buy/sell on university campuses, prices in naira). **Frontend connected to Supabase (read-only)**: when `VITE_SUPABASE_URL` + `VITE_SUPABASE_KEY` are set (`.env.local`, never committed), all product queries go through the `catalog_search` RPC (one row per offer, tier-ordered same campus → same state → everywhere else), location pickers from the `campus_directory` view, and categories from their own small query; when either variable is missing the app shows a friendly "**Wemart is being set up**" screen (`SetupNotice.tsx`) instead of attempting broken calls. Location model is **STATE → CAMPUS only** (two linked selects, no city/region tier). Prices are in naira and render **as-is, never divided**. **Publishable (anon) key ONLY — never a service_role or secret key in the bundle.** No login, cart or checkout yet.

- Stack: Vite 8 + React 19 + TypeScript 6, Tailwind CSS **v4** (plugin `@tailwindcss/vite` in `vite.config.ts`; styling entry is `@import "tailwindcss"` in `src/index.css` — there is **no `tailwind.config.*` file and none should be added**)
- Deploy target: Cloudflare **Workers** static assets (`npx wrangler deploy`; config in `wrangler.toml` with `not_found_handling = "single-page-application"`). `npm run build` → `dist/`. There is **no `public/_redirects` file** — a catch-all SPA rule like `/* /index.html 200` fails Workers validation with "Infinite loop detected"; never recreate it. (Cloudflare *Pages* would still work via `npx wrangler pages deploy dist`, where `_redirects` is the fallback — but the current pipeline is Workers)

Rules (all intentional — keep consistent):
- **No decorative stars; the logo is the only star.** The `wemart-logo.png` in the header (and the favicons) are the only star assets; there is no starburst component or SVG/CSS star anywhere in the UI.
- **Hard offset shadow** `3px 3px 0 0 ink`, no blur, no soft grey shadows, no gradients — via the `hard-shadow` utility. Applied to primary buttons (always) and product cards (on hover/press only).
- **One radius for cards and buttons: 8px** (`rounded-lg`). Pill shape only for category chips.
- **Primary button**: `bg-orange text-ink`; hover `bg-orange-deep text-white`. The hard shadow stays on hover and collapses on press (`active:translate + shadow-none`). **Text on orange backgrounds is always Ink `#181311`, never white.** Any orange text on white uses `orange-deep`.
- **Layout**: sticky header (logo, compact State + Campus selects, cart); compact hero with headline "Discover on Wemart.", supporting line, search box + "Filters" button (badge = count of active filters), removable active-filter chips ("Clear all" link), "Sell an item" primary button — all above the fold on a phone; horizontally scrolling top-level category chips plus a sub-category chip row when the chosen top-level category has children; product grid 2 columns on phones, 3–4 on wider screens; mobile-only bottom nav (Home, Browse, Sell, Orders, Me).
- **Result sections (matching first, never unrelated items mixed in):** with `label` = sub-category name, else category name, else the search text in quotes, else "items", and `place` = chosen campus name, else chosen state name. Campus chosen → rows are grouped by scope (same campus → same state → elsewhere — catalog_search already orders them so) and rendered in that order under the headings **"{label} at {campus}"**, **"Also in {state}"**, **"In other places"** (empty groups are skipped); state-only → **"{label} in {state}"** then **"In other places"**; no location chosen → one list, no scope headings. If the matching place has no rows but other scopes do, a notice sits at the top — **"No {label} at {place} yet."** (campus) / **"No {label} in {place} yet."** (state) with the second line **"Here are {label} from other places:"** — followed by the other groups. If there are NO rows at all: the compact centered message **"No matching products found"** with the second line **"We couldn't find a product matching your current search. Explore other available items below."** — no buttons and no oversized panel inside the empty state (the "Clear all" link lives in the filter-chips row above, not in the empty section) — then one `getRecommended` fallback query (location filters + in-stock only) shown immediately below under the clearly-labelled **"Recommended Products"** heading (up to 12 cards; RPC tier ordering ranks proximity campus → state → elsewhere with `price_asc` making each group cheapest → most expensive, and with no location preference everything is cheapest first; every card keeping its own campus + state line, never blended into matching results). Loading skeletons and an error state with Retry stay; the **"New arrivals" strip is hidden whenever the current view is empty** (its latest items are unrelated to the failed search and would appear above the empty message, plus it would duplicate the recommended cards); the count line reads "{n} items found" and switches to "{n}+ items found" while another page may exist.
- **Product cards**: real Storage photo when `image_path` exists (lazy, width/height set, broken URLs degrade to the placeholder), otherwise CSS emoji placeholder; product name (+ variant name when present), **plain bold price in ink under the name**, condition tag (New / Used / Refurbished / Other), vendor shop name, actual located campus + state name ("ABU, Kaduna") — offers with neither campus nor state show no location line rather than a fabricated one; availability marker — green "In stock" for in-stock, neutral "Sold out" otherwise. No verified check icon (no flag exists yet).
- **A11y/perf**: global visible `:focus-visible` outline (ink); `prefers-reduced-motion` disables transitions/animations; the page stays light for mobile data (no image URLs, self-hosted subsets only).
- The cart is intentionally an empty-state panel — **no fake checkout flows** (see Rules).

## Rules

- **Data rules (binding for any future change):**
  - Prices are naira. Render `price` as-is through `Intl.NumberFormat('en-NG', { style: 'currency', currency: 'NGN', maximumFractionDigits: 0 })` — **no division, no kobo conversion**
  - Products are read ONLY through the `catalog_search` **RPC** via `src/data/api.ts` (one row per offer; the `catalog` view is never queried from the browser directly). State/campus options come from the `campus_directory` **view**; the national directory itself covers all 36 states + FCT (~110 campuses). SQL migrations and seeds are NEVER applied automatically from this repo — every file in `database/` is review-first and must be run by hand in the Supabase SQL editor after review
  - **Never read `vendors`, `vendor_locations`, `buyers`, `orders` or `payments` from the browser.** Public vendor display info arrives pre-joined in the view
  - There are no verified or featured flags yet; do not invent them in the UI
  - Use the **publishable (anon) key only. The service_role key must never appear in `src/`, `.env.example`, or any `VITE_` variable** — that would leak admin access in the public bundle
- **Supabase is connected (read-only) but live data is UNVERIFIED end-to-end.** The frontend reads only the `catalog` view + `locations`/`categories`; do not claim live listings work in a report until a real query returns data in a deployed session. Never run destructive SQL on the live project from this repo; never disable RLS
- **Do not implement payment processing or pretend transactions are real.** No fake checkout flows
- **Never put secret keys anywhere in `src/` — everything becomes public in the `dist/` bundle.** If an API key is ever needed, keep it behind a Cloudflare Worker/proxy, not the front end. `VITE_`-prefixed env vars are also public
- Mobile-first: design for phones first, add `sm:`/`lg:` breakpoints upward (existing components follow this)
- `npm run build && npm run lint` from the repo root are the verification gates (build runs `tsc` typecheck + bundle; lint is `oxlint`). Run both before declaring work done
